# RTOS kernels on actual RTL CPU masters

FreeRTOS Kernel 11.2.0, µC/OS-II 2.93.01 and µC/OS-III 3.08.02 have
source-built RV32 M-mode conformance applications for both supported external
CPU profiles: Chipyard Ibex and custom Ibex with writeback/branch-target ALU.
The RTL executes instructions; QEMU qtest or the gem5 atomic master owns physical
memory and native UART/CLINT/PLIC. No ISS executes guest instructions in this mode.
This dedicated workflow supplements `usp platform`; its existing YAML RTL
workload selector still accepts bare-metal only.

Both µC/OS products and their selected SiliconLabs dependencies use Apache-2.0.
FreeRTOS retains its MIT notice. Source pins are:

| Repository | Commit |
|---|---|
| SiliconLabs/uC-OS2 | bfc6120f20cb27a927a9fc5dd667f9e455495777 |
| SiliconLabs/uC-OS3 | 9a3fc5f45d75c0b4c3b6eaecf903720c74329747 |
| SiliconLabs/uC-CPU | ae5796e2049b043f69ef4f29fc330f29217b6344 |
| SiliconLabs/uC-LIB | 71b5f65da27859028a89c4ceac1df53c880916dc |

The upstream checkouts remain clean. The build copies configurations and ports
into its output, preserves notices and records source/header, compiler, command,
adapter and artifact hashes. The µC/OS software-interrupt address is adapted from
the upstream PRCI constant to IR-derived CLINT MSIP. The µC/CPU header selects its
actual C CLZ/CTZ implementations because its assembly file lacks those routines.
The original kernel schedulers, task stacks, software-interrupt context switches
and timer tick handlers are compiled and executed. Ibex requires vectored mtvec
and starts at RAM+0x80; the generated reset/vector code implements that contract.

The RV32 FreeRTOS adapter uses its upstream GCC port, an explicit uintptr_t cast
for its 64-bit timer address and a 32-bit tick type. Its two equal-priority
register-check workers never yield. The timer must preempt both before a delayed
supervisor can pass; UART/PLIC notification must arrive through the ISR.
The µC/OS application delays a high-priority task thirty times while a lower
priority register-check worker never yields. It also verifies UART interrupts,
four actual Chipyard GCD results/interrupts and OpenTitan GPIO output/input,
interrupt and W1C behavior in the same running system.

All applications use a 10 kHz tick generated by the engine CLINT. This bounds RTL
regression cost; it is a conformance setting, not a calibrated CPU performance
model. Metrics remain real RTL clock/RVFI counts. Peripheral timing is still
transaction-driven; global cycle correlation, DMA and coherence are not inferred.
No FPU/vector state, supervisor mode, MMU, Linux, SMP, Rocket/BOOM or arbitrary
RTL protocol support is claimed. FreeRTOS custom-IP drivers are still separate;
the µC/OS application currently exercises those devices directly from a task.
Zephyr has its own verified source-built RV32 RTL BSP and driver acceptance;
see [rtl-zephyr.md](rtl-zephyr.md).

Use the previously verified CPU/model/generated directories described in
[RTL CPU adapters](rtl-cpu-adapters.md). With GCC 14.2.0, the provisioned FreeRTOS
source and native executables on PATH, run:

```sh
export USP_FREERTOS_SOURCE="$PWD/.tools/upstream/freertos"
export USP_IP_MODELS_DIR="$PWD/build/source-ip-models"
export USP_IP_GENERATED_DIR="$PWD/build/rv64-ips"
export USP_DUAL_BUILD_ROOT="$PWD/build"
export USP_RTL_CPU_IBEX_BUILD="$PWD/build/rtl-cpu-ibex"
export USP_RTL_CPU_CUSTOM_BUILD="$PWD/build/rtl-cpu-custom"
export USP_RTL_MASTER_BUILD="$PWD/build/rtl-master-gem5"
# Choose fresh output roots; existing outputs are deliberately not overwritten.
export USP_RTL_OS_ROOT="$PWD/build/rtl-os-candidate"
export USP_UCOS_ROOT="$PWD/build/ucos-candidate"
bash scripts/rtl_os_bringup.sh
```

The script fetches exact public µC/OS source pins, builds three positive maps
(rv64-ips, AI_SOC and AIZ_SOC) and two negative firmware cases per kernel, then
runs 42 actual tests: 14 FreeRTOS and 28 µC/OS. Each positive matrix includes both
RTL CPUs and both memory engines. Negative firmware deliberately fails or disables
ticks; success cannot be obtained merely by printing a banner. Verification also
rejects a modified compiled software source or port. JUnit is written to
`build/rtl-os-junit.xml`. Missing required native tools fail this gate.

For a single µC/OS run:

```sh
usp ucos build examples/rv64-ips --generated build/rv64-ips \
  --upstream .tools/upstream --kernel ucos3 --out build/ucos-single
usp ucos run examples/rv64-ips --generated build/rv64-ips \
  --firmware build/ucos-single --manifest models/cpus/chipyard-ibex.yaml \
  --cpu build/rtl-cpu-ibex --models build/source-ip-models --engine gem5 \
  --bridge build/rtl-master-gem5 --out results/ucos-single
usp ucos verify results/ucos-single
```

`usp rtl-os build/run/verify` provides the analogous FreeRTOS path, with `--source`
instead of `--upstream/--kernel` at build time. Run bundles retain the ELF, copied
software/port sources and license notices, UART, MMIO/IRQ traces, native CPU
reports and an independently verified `os-report.json`. Promotion requires
USP_REQUIRE_RTL_OS/USP_REQUIRE_UCOS and both build-root variables. The manual
`rtl-os.yml` workflow uses provisioned self-hosted tools; local results do not
establish that a hosted runner or branch protection has been enabled.
