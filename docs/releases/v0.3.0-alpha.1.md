# v0.3.0-alpha.1 — common native IR and direct IP-XACT intake

Package: 0.3.0a1. This is an incremental M1 alpha in the owner-approved
v0.3/v0.4/v1.0 programme, not complete M1-M4 or universal industrial SoC support.

The native YAML and direct structural IEEE 1685-2022 frontends converge into a
validated immutable native IR. It retains per-hart CPU/boot contracts, clocks,
cold reset, model/region/register/parameter/hierarchy identity, address spaces,
interrupt routes and source hashes. QEMU, native gem5 and firmware lowering use
the checked IR projection. The prior soc-ir.json is a checked compatibility view.

Direct examples include AI_SOC/AIZ_SOC high physical SMP maps and a hierarchical
GCD cluster with explicit aliases. Exact VLNV, width, aperture, CPU and declared
register contracts are checked before output. Unknown bus/translation semantics
remain unsupported; no behavioural inference or CPU substitution is introduced.

Local promotion requires all previous native cases plus direct-IP-XACT
bare-metal/Linux on both engines and the hierarchical MMIO/IRQ case. Linux
acceptance now requires every declared SMP hart online. Actual test counts and
SHA256-protected JUnit are attached to the annotated release tag after the gate;
failed and negative run evidence is retained separately.

The package/CLI/lock versions match the tag. The application version is separated
from hardware compiler code for subsequent version-only changes. Legacy generated
outputs affected by that migration must be regenerated; explicit QEMU reuse
requires matching original source/C/manifest/binary identities and records reuse.
Software build records are never rehashed to silence a stale-build check.

This source prerelease does not publish a new SDK image. Existing immutable
container-v0.2.0-r1 remains the qualified SDK/environment release; its wrapper
selects checkout source through PYTHONPATH. SDK source builds/releases must use
their matching container tag until a new packaging revision is qualified.
Hosted native, cold all-engine rebuild and new Podman/OCI acceptance remain
separate from local incremental qualification. The application release workflow
publishes wheel/sdist and distinct local/hosted-minimal evidence after its checks.

Open exits: general bus/abstraction/view/translation and reset semantics,
heterogeneous/RTL CPU lowering, richer external transactions/DMA/coherence,
generic Zephyr/RTOS/Yocto generation, global timing calibration and matching
full-inventory RTL/ASIC designs. See versioned-upgrade-plan.md and
native-design-capabilities.md. Public technology evaluation is not production
sign-off. A Git tag alone is not proof that GitHub release assets were published.
